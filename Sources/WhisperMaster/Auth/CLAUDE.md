### Authentication — Clerk sign-in, the account gate (`Auth/`)

**A user can dictate before sign-in. Sign-in is still required for sync, the assistant and the beta track.** That is owner decision **D2, 2026-11-27**, and it replaces the earlier rule that gated the whole app behind sign-in at launch. It is a deliberate choice layered on top of the otherwise local-first design: transcription runs entirely on-device, and only sign-in itself and the account's sync talk to Clerk's cloud and the dashboard.

- **One table: `AccountFeature` (`Auth/AccountGate.swift`).** `.dictation` is open; `.sync`, `.assistant` and `.betaUpdates` need a session (`isAllowed(signedIn:)`). A call site asks the table with the App layer's own answer (`AppDelegate.isSignedIn`), never the Clerk session itself, and `AccountGateTests` pins every row, including "dictation is the only feature open without an account". **No `authBypass`-style flag, in any build.** Signed-out access never opens anything the table closes, and sign-in itself is still real Clerk sign-in. Add a feature by adding a case: it is behind an account until someone decides otherwise.
- **Config (`Auth/ClerkConfig.swift`).** The publishable key is client-safe, read from `Info.plist` `ClerkPublishableKey` (env `CLERK_PUBLISHABLE_KEY` overrides for dev). **You must set a real `pk_test_…`/`pk_live_…` key** or sign-in shows an "add your key" message (dictation still works) — a missing/placeholder key is treated as unconfigured and we never call `Clerk.configure` with it (its validation `assertionFailure`s in debug). `configureIfPossible()` runs first thing in `applicationDidFinishLaunching`, before anything reads `Clerk.shared`.
- **Sign-in window (`Auth/AuthGateWindow.swift` + `AuthGateView.swift`).** A `NSWindow` hosting SwiftUI `AuthView(isDismissible: false)` from `ClerkKitUI`, injected with `.environment(Clerk.shared)`. It opens **only when the person asks** (`AppDelegate.presentAuthGate()`: the tray's **Sign In…**, the Settings account popup and the sign-in panels, a tap on the notch sign-in prompt) and has a **close button**: they can close it and keep dictating (it was close-button-less while the app was gated). Shows a spinner while Clerk restores a persisted session; the setup message when unconfigured. `AuthGateView` shows **only `BrandLogo` above the card** — Clerk's `AuthView` renders its own header that has no public hide toggle, so a custom wordmark+tagline on top duplicated it.
- **OAuth social sign-in needs each build's redirect URL allowlisted in the Clerk dashboard (server-side, not code).** Clerk's iOS/macOS SDK does social OAuth (Apple/Google/X) via `ASWebAuthenticationSession` with redirect `{bundleIdentifier}://callback` (the SDK default; we pass no `redirectConfig` override). Clerk's API **rejects the request** with *"The current redirect url … does not match an authorized redirect URI for this instance"* unless that exact URL is on the instance's allowlist. Because the instance is keyed on bundle id (above), the three builds need three different URLs across the **two** instances — add each in **Clerk Dashboard → Configure → Native applications → "Allowlist for mobile SSO redirect"** (or via the Backend API `POST /v1/redirect_urls` with that instance's `sk_…` key), in the **matching instance**: `app.whispermaster.mac://callback` **and** `app.whispermaster.mac.beta://callback` on the **live** instance (`whisper.corkkam.com`); `app.whispermaster.mac.dev://callback` on the **dev** instance (`sweeping-humpback-68`). This is **not** the "Restrictions → Allowlist" page (that gates sign-*ups* by identifier, a different Pro feature). Email OTP works without any of this — only the OAuth buttons use the redirect. No rebuild needed; it takes effect on the next sign-in.
- **Launch does not wait for Clerk (`SessionResolution`, `AppDelegate.reconcileAuthGate`).** `applicationDidFinishLaunching` starts what dictation needs at once (`startDictationServices`: the speech model download or load, the opt-in LAN server, the mesh). The 0.5s timer then runs `reconcileAuthGate()`, which reads `Clerk.shared.user`/`isLoaded`. Clerk restores a saved session asynchronously, so every user looks signed out for a moment; setup is scoped to the account, so `settleLaunchIfNeeded()` (the Globe-key claim, setup or the quiet notification prompt, the Settings window if the model still needs installing) waits for the answer, and stops waiting after **`SessionResolution.grace`, 4 s**, because offline Clerk may never answer. It runs once. The silent `checkForUpdateInformation()` also waits (`checkForUpdateInformationIfAccountChanged`) and runs again for each account, because `BetaAccess` reads the session.
- **The two directions of `reconcileAuthGate`.** Signed in: close the sign-in window, `startAccountServices()` (coding agents, the day row, call detection), `revealAccountSurfaces()` (the hover band, and setup for an account that has not finished it), then `activate(userID:)` on the usage, notes, connector and agent-memory stores and `Analytics.identify`. Signed out: `stopAccountServices()`, `hideAccountSurfaces()`, `deactivate()` on those stores and `Analytics.resetIdentity()`. Every call is idempotent, because this runs twice a second. `AppState.accountSignedIn` mirrors the answer for the views (`DictationViewModel.setAccountSignedIn`, guarded) and gates nothing.
- **Enforcement points.**
  - **Dictation is not gated.** `ensureCanDictate()` asks `AccountFeature.dictation` (always true) at every capture entry point: push-to-talk `.start`, `.toggle` and `.handsFree`, the tray's `startRecording`, the Settings and Today mic cards. Setup can still hold a press (`onboardingAllowsCapture()`). `showWindow()` and `showOnboarding()` open signed out; both wait out a sign-out in flight. `DictationViewModel` stays Clerk-free; all auth lives in the App layer.
  - **The assistant** (`ensureCanUseAssistant()`, `AccountFeature.assistant`): the fn + control chord's `.engaged`, the coding-agent key's `.start`, and every start of meeting notes (`startMeetingNotes()`). Signed out, the chord shows the notch sign-in prompt instead of running (`DictationViewModel.refuseForSignIn`); a session fn had already opened has its words **held, never pasted and never dropped** (`holdWordsUntilSignedIn`: clipboard, history, band). Details: `Input/CLAUDE.md`. A tap on the prompt, which is the command-confirmation band, goes through `onOpenNotes`, which opens sign-in when there is no session. Connectors, the account's notes and reminders and the coding-agent and day services start only with a session.
  - **Sync** (`AccountFeature.sync`): `refreshStatusItem()` passes the policy into `usageSync.syncIfNeeded(enabled:)`, `notesSync.pullIfNeeded(enabled:)` and `notesSync.syncIfNeeded(enabled:)`, and the clients themselves send nothing without an identity (`currentUsageIdentity()` is nil without a user). Both are tested. Usage is also not **recorded** signed out (`UsageStore.record(_:owner:)` skips an ownerless session with a notice).
  - **The beta track** (`AccountFeature.betaUpdates`): `BetaAccess.allowedChannels` returns the empty set, which Sparkle reads as "stable only", when signed out (`allowedChannels(signedIn:betaFlag:)`, tested).
  - **The pages made of an account** (`SettingsSection.requiresAccount`: Notes & Reminders, Connectors, Insights) show `SignInRequiredPanel` signed out.
- **A way back in, signed out.** The tray shows **Sign In…** in place of Sign Out (change-guarded on the tick); the sidebar account row reads "Not signed in / Sign in to sync" and its popup (`AccountSignedOutCard`) has a Sign in button; each account page has the same button.
- **Setup is scoped to the account, or to this Mac when signed out.** `OnboardingProgress.signedOutScope` (`"signed-out"`, which cannot be a Clerk id, since those start `user_`) holds a signed-out person's record, so setup does not return at every launch. Signing in with the permissions already granted seeds the account as seen, so they are not shown it twice.
- **A sign-out holds the account's surfaces down until Clerk answers (`SignOutHold`, `App/OnboardingLaunchDecision.swift`).** `signOut()` hides the account's surfaces and deactivates its stores first, then awaits the network call, and until that returns `Clerk.shared.user` stays set — so the next tick's signed-in branch used to reveal the app again. The hold is set before `hideAccountSurfaces()`; while it is set, `reconcileAuthGate()` only hides, `isSignedIn` is false (so nothing syncs and the assistant stays closed during it), `showWindow()` and `showOnboarding()` wait, and `OnboardingLaunchDecision` returns `.skip`. It ends when the call returns (success or failure), or after **`SignOutHold.limit`, 75 s**, a bound of our own set above the 60 s request timeout of the session Clerk's client uses, so it only ends a call that hangs. Only the newest sign-out's end clears it. An offline failure leaves the session, so the app comes back signed in, as before. In-memory only. The app **carries on signed out afterwards**: it does not re-show a window.
- **Account surfaces: hide and re-show.** `hideAccountSurfaces()` takes down what is made of the account's data — the Settings window, the hover band, the meeting live window — and releases setup without marking it seen. The dictation pill stays. `revealAccountSurfaces()` runs `showOnboardingIfPending()` and starts the hover band. `appSurfacesHidden` starts true (nobody has signed in yet) and flips once per transition.
- **Analytics keep their rules.** Events stay content-free and account-free; signed out, the install id is the identity (`Analytics.identify` runs only with a session, `resetIdentity` without one), and the opt-out gates every send. The per-person usage totals are written only for a session an account owned.
